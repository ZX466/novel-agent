## Pi 性能评估结论（已定，直接采纳为设计约束）

1. **注入必须进 system prompt，不得拼进 topic**——否则 retrieval query 每次变化，embedding 缓存全 miss（+100-500ms/次网络 embed）。
2. **token 预算**：三项注入合计 +400-1400 tokens/次（+7%~25% input），可接受。人物树**限 10 角色内**、relations 单行精简，避免把 6000 字符 lore 顶到 8000+。
3. **字数重试策略（按此设计）**：
   - 差距 ≤10% → 接受不重试
   - 少 10%-40% → continue 分支续写补足 1 次（成本仅整章重生 15-25%）
   - 差距 >40% 或续写 2 次仍不足 → 才整章重生
   - **不要把字数绑进 evaluate 评分**——会高频触发迭代，破坏 pipeline_max_iters=3 成本上限
4. 现有管线参数：draft max_tokens=4096、refine 2048、pipeline_max_iters=3、_HARD_MAX_ITERS=5。

## 1. 设计目标

将章节数、人物关系树、前文梗概、字数目标注入 **system prompt（system_content）**，而非 topic；字数重试不绑 evaluate 评分（遵守 Pi 性能分析结论 §3）。

## 2. 数据流设计

### 2.1 新增 PipelineState 字段（state.py）

```python
# state.py PipelineState 新增（total=False，向后兼容）:
chapter_index: int | None             # 当前章 0-based index（来自前端 activeChapter）
total_chapters: int | None            # 大纲总章数（来自前端 outline heading count 或 targetChapters）
chapter_title: str                     # 当前章标题（来自前端，可空）
target_word_count: int | None         # 用户/前端指定目标字数（可空=自动推导）
writing_context: str                  # retrieval_node 填充的结构化写作上下文（system prompt 注入用）
```

### 2.2 传参链路

### 2.3 前端变更

- `DefaultChatTransport` 目前无 `prepareSendMessagesRequest` / body 自定义（AIToolPanel.tsx:274-284），只发 `{messages}`。需扩展为 `prepareSendMessagesRequest` 回调，在 body 中追加 `chapter_index`、`total_chapters`、`chapter_title`、`target_word_count`。

## 3. 写作上下文构建（_build_writing_context）

新增 `nodes.py` 内部函数（或 `retrieval.py` 扩展），输入 `state`，输出结构化文本块：

### 3.1 章节进度

```
【章节进度】
当前：第{chapter_index+1}章《{chapter_title}》
进度：{chapter_index+1}/{total_chapters}（{百分比}%）
```
- 数据源：`state["chapter_index"]`、`state["total_chapters"]`、`state["chapter_title"]`
- 任一缺失则跳过该行，不注入"未知"占位

### 3.2 人物关系树概要

```
【人物关系树】
- {name}（{role}）：{description}；弧线：{arc_summary}；关系：{relations}
```
- 数据源：`retrieve_structured_lore` 已查 `Character` 表（retrieval.py:462-482），可直接复用查询结果。需额外从 `PlotEvent.involved_character_ids`（plot_event.py JSONB 数组）提取共现关系。
- **关系推导**：遍历 PlotEvent，若 `involved_character_ids` 含 ≥2 个角色，生成 "{A}—{B}：共同经历「{summary}」" 关系行。同一对角色出现多次时合并为 "A—B：共同经历事件1、事件2"。
- **限制**（遵守 Pi 结论 §2）：最多 10 个角色、每角色 1 行精简；relations 合并到 2 条以内；整块 ≤2000 字符。
- 无 Character 数据时返回空，不注入该块。

### 3.3 前文背景（最近 1-2 章梗概）

```
【前文背景】
- 第{N-1}章《{title}》：{summary or content_text[:300]...}
- 第{N-2}章《{title}》：{summary or content_text[:300]...}
```
- 数据源：`Chapter` 表 `WHERE novel_id=? AND chapter_index < {current} ORDER BY chapter_index DESC LIMIT 2`
- `summary` 为空时取 `content_text[:300]` 作为梗概（标注"前文摘录"）
- 无前序章节时返回空

### 3.4 字数目标

```
【字数要求】
本章目标：{target_min}-{target_max} 字（正文 codepoint 计，不含标题/空白）
```
- 推导优先级：
  1. 前端 `target_word_count` 非空 → `target = target_word_count`
  2. 前 ≤5 章 `word_count` 中位数 → `target = median`（抗异常值）
  3. 无前序章节 → `target = 1000`（默认）
- 区间：`target_min = round(target * 0.85)`、`target_max = round(target * 1.15)`（±15%）
- 硬约束措辞：`必须控制在 {target_min}-{target_max} 字以内，不足或超出过多视为不合格。`

## 5. 字数重试策略（不绑 evaluate）

遵守 Pi 性能结论 §3，在 `draft_node` 完成 streaming 后、返回 state 前加 post-check：

```python
# draft_node 尾部（streaming 完成后）
if task_type == "generate":
    draft_text = content  # 已 strip think tags 的最终文本
    wc = _count_codepoints(draft_text)  # 复用 len() 口径
    target = _resolve_target_word_count(state)
    if target and wc > 0:
        ratio = wc / target
        if ratio < 0.6:
            # 标记需要整章重生（写入 state 供 refine 阶段或 fallback 处理）
            return {"draft": draft_text, "_word_count_retry": "regenerate"}
        elif ratio < 0.9:
            # 标记需要续写补足
            return {"draft": draft_text, "_word_count_retry": "continue"}
    return {"draft": draft_text}
```

- `refine_node` 读取 `_word_count_retry`：`continue` → 追加续写指令（"请在现有正文基础上续写约 {target - wc} 字，保持风格衔接"）；`regenerate` → 替换 system_content 中的字数强调后重跑 draft。
- **不修改 evaluate_node 评分逻辑**，不把字数加入 ReviewMatrix 维度。
- 超出 `pipeline_max_iters=3` 时接受当前结果并在 `_word_count_retry` 中记录原因。

## 7. 风险与待决项

- **前端 transport 扩展**：`DefaultChatTransport` 是否支持 `prepareSendMessagesRequest`？需查 AI SDK v5 文档确认。若不支持，fallback 方案是退回在 `sendMessage({text})` 的 text 里编码 `[chapter:N]` `[total:M]` `[target:W]` 标签，后端 `_extract_*` 解析（但违反"不进 topic"原则，仅作 fallback）。
- **字数口径不一致**：`Chapter.word_count` = `len()`，前端 `countWords` = CJK+分词。建议后端统一用 `len(content_text)`（codepoint），前端也对齐。但这属于兼容性域范畴，需 Claude 确认是否本次一并改。
- **人物关系推导精度**：`PlotEvent.involved_character_ids` 是 JSONB 数组，无关系类型（敌/友/师徒）。当前设计只输出"共同经历"，不臆造关系类型。若需更精确的关系，需后续加 Character 关系表或 attributes 中的 relationship 字段。
