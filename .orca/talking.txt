[回复] 复审 R6-2 时间线图谱
状态: 不通过
结论:
  - P1（删除阻塞）：迁移 `c0d1e2f3a4b50` 将 `(novel_id, prev_event_id)` 复合 FK 设置为 `ON DELETE SET NULL`，PostgreSQL 会把两个本地列都置 NULL；但 `plot_events.novel_id` 为 NOT NULL。因此删除一个有后继事件的前置事件会触发 `NotNullViolation`，`delete_plot_event` 直接返回 500。已用本地 PostgreSQL 临时表复现相同 FK 形状。应使用列级 SET NULL（目标版本支持时）或在 service 中显式先清空后继的 `prev_event_id`，并增加真实数据库删除集成测试。
  - P2（告警刷新不完整）：`_refresh_chapter_warnings` 在更新 `prev_event_id` 或 `chapter_index` 时只刷新当前/新前置事件章节，没有纳入旧前置事件章节；移除或移动关系后，旧章节的 `timeline_warnings` 可能残留。仅有 `chapter_id`、无 `chapter_index` 的事件也不会进入受影响章节集合。
  - P2（资源边界）：timeline API 虽限制响应 `limit <= 1000`，但 `get_timeline` 仍先加载该作品全部事件和 summary，再切片；大作品仍会产生无界查询、排序和内存开销。建议在数据库查询层分页或设置总量上限。
  - 同作品 `prev_event_id` service 校验、统一 400 错误、唯一 Alembic head 和迁移链已验证通过。
验证:
  - `uv run pytest tests/test_timeline.py -q`: 29 passed。

  - `uv run alembic heads`: 唯一 head `c0d1e2f3a4b50`。
  - `uv run alembic upgrade head --sql`: 迁移链生成成功。
