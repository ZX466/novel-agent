[回复] 修复: AI 文本插入编辑器后分段(换行)消失
状态: 已完成（诊断+建议，按约定不实施编码）
根因:
  editor/page.tsx:617 handleInsertIntoEditor 用 `editor?.chain().focus().insertContent(text).run()` 直接插纯文本。TipTap `insertContent(字符串)` 默认按 **HTML 解析**：无标签纯文本中的 `\n` 被视为空白折叠 → 多段挤成一段。同病 4 处：:638 handleReplaceInEditor 的 insertContentAt(from, text)、:640 兜底 insertContent(text)、:470 与 :496 两处 find-replace 的 insertContentAt(m.from, replacement)（AI replacement 含换行同样折叠）。
最小 diff 建议:
  1. 新增纯函数（建议 frontend/src/lib/insertText.ts）：
     ```ts
     import type { JSONContent } from "@tiptap/core";
     export function textToParagraphNodes(text: string): JSONContent[] {
       return text.split("\n").map((line) => ({
         type: "paragraph",
         content: line ? [{ type: "text", text: line }] : undefined,
       }));
     }
     ```
     逐 `\n` 映射 paragraph；空行 → 无 content 空段，忠实还原原空行分段（`\n\n` 中间空行成为空段，视觉保留"空行分段"）。
  2. 上述 5 处调用统一改传 `textToParagraphNodes(...)`（抽一处共用，避免转义面）。备选"字符串转 HTML(`<p>`/`<br>`)再插"不推荐——需自行转义 `<>&`，XSS/转义面更大；节点数组纯结构无转义问题。
  3. 光标行为：insertContent 仍在当前 selection 插入、不覆盖既有内容，无需额外处理；如需插入后光标落到文本之后可链尾加 `.setTextSelection("after")`（可选）。
  4. 测试用例建议（补 1 个换行保留）：vitest 单测 `textToParagraphNodes("A\n\nB\nC")` → 4 个节点（空段 / A / B / C）；若已有 editor 测试基建，可加插入后 `doc.toJSON()` 分段断言。
  验收对照：①3+ 段逐段保留——节点数组方案直接满足；②光标点不回归——insertContent 语义不变；③tsc——同改名任务备注（EALLOWREMOTE 环境限制，建议合入后统一补跑）。
